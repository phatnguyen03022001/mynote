# Architecture Decision Records

ADRs capture decisions that are expensive to reverse or constrain future design. They are not changelogs and should not record routine implementation choices.

Each ADR states context, decision, consequences/trade-offs, and status. When superseded, keep the old ADR and point to the replacement so decision history remains intelligible.

Current records:

- `0001-modular-monolith.md` — deploy as one Next.js modular monolith.
- `0002-mongodb.md` — MongoDB as application/auth persistence platform.
- `0003-authentication.md` — Better Auth with Google/GitHub social providers.
